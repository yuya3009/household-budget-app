# Vercelを使用しない理由

作成日: 2026-10-31

## 結論

ホスティングには Vercel ではなく **Render** を使用する。

## 主な理由

Vercel はフロントエンドしかサポートしておらず、Render はフロントエンド・バックエンド・DB のすべてを使用できるため。

## Renderでの構成例

- **フロントエンド（React）**：Static Site として配信。`npm run build` で作られた成果物を配信するだけなので、設定は簡単。
- **バックエンド（Node.js）**：Web Service として常時起動。Express などで API を作る。
- **データベース（PostgreSQL）**：Render の Managed PostgreSQL を作成し、バックエンドから接続情報を環境変数で渡す。

フロントとバックエンドを同じ Render 上に置けば、サービスの管理画面、環境変数、デプロイの流れを一箇所で扱える。

## Vercelを使うメリット・デメリット

- **メリット**：フロントエンドのプレビュー環境（PRごとの公開URL）が便利。
- **デメリット**：
  - Node.js のバックエンドは Vercel の関数として動かす形になり、常駐サーバーや長時間処理には向かない。
  - DB も別サービス（Neon、Supabase など）が必要になり、管理するサービスが増える。

## 最初に確認しておきたい点

- Render の無料枠の PostgreSQL は期限付きだったり、一定期間で削除されたりする仕様がある。本番運用するなら有料プランを前提に考えるのが安全。料金と条件は公式サイトで最新版を確認すること。
- 開発中の確認はローカルの PostgreSQL（Docker など）で行い、本番だけ Render の DB を使うと安全。
