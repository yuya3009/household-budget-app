### 0. 凡例

#### 0-1. 構成要素

| 構成要素 | 図での表し方 | 説明 | 本書での例 |
|---|---|---|---|
| アクター | 人型のアイコン | システムを利用する人間や外部システム | ユーザー、スケジューラ（cron） |
| オブジェクト | 四角い箱 | 処理を行う画面やサーバー、データベースなどの実体 | 画面（React）、APIサーバー（Node.js）、DB（PostgreSQL） |
| ライフライン | オブジェクトから下へ伸びる垂直の破線 | 時間の経過を表す（上から下へ時間が進む） | 各アクター・オブジェクトの下に伸びる線 |
| 実行仕様（活性化） | ライフライン上の細長い長方形 | 処理を実行している期間を示す | APIサーバーがリクエストを処理している間 |
| メッセージ（同期） | 実線の矢印（──▶） | 呼び出し元が応答を待つ指示・データの送信 | `POST /api/expenditures` |
| メッセージ（応答） | 破線の矢印（--▶） | 同期メッセージに対する戻り値・結果 | `201 Created` |

#### 0-2. 補助的な表記

| 表記 | 説明 |
|---|---|
| `alt` / `else` の枠 | 条件分岐。枠内のいずれか1つだけが実行される（例：入力エラー時／正常時） |
| `loop` の枠 | 繰り返し処理 |
| 自分自身への矢印 | オブジェクト内部の処理（入力チェック、画面描画など） |
| 黄色の付箋（Note） | 補足説明・未決事項 |

#### 0-3. 凡例図

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor A as アクター
    participant B as オブジェクトB
    participant C as オブジェクトC

    Note over A,C: 各要素の下に伸びる破線 ＝ ライフライン（上から下へ時間が経過）

    B->>+C: 同期メッセージ（実線）

```

### 1. ホーム画面表示（SCR-001 / FUC-011）

アプリ起動時にホーム画面を開き、当月の収支と月次収支推移を表示する。

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor U as ユーザー
    participant FE as 画面（React）<br>SCR-001 ホーム
    participant API as APIサーバー<br>（Node.js）
    participant DB as DB<br>（PostgreSQL）

    U->>+FE: アプリを開く
    FE->>+API: GET /api/reports/monthly-summary
    API->>+DB: 収入・支出を月ごとに集計（GROUP BY）
    DB-->>-API: 月別の収入合計・支出合計
    API-->>-FE: 200 OK（data: month / income_total / expenditure_total）
    FE->>FE: 当月の収支と月次収支推移グラフを描画
    FE-->>-U: ホーム画面を表示
```

### 2. 支出・収入登録（SCR-002 / FUC-001）

支出と収入は別エンドポイントのため、選択した収支区分によって呼び出すAPIが変わる。

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor U as ユーザー
    participant FE as 画面（React）<br>SCR-002 収支入力
    participant API as APIサーバー<br>（Node.js）
    participant DB as DB<br>（PostgreSQL）

    U->>+FE: 収支区分・日付・カテゴリ・金額・メモを入力し「記録する」
    FE->>FE: 入力チェック（必須項目、金額1〜999999）

    alt 収支区分＝支出
        FE->>+API: POST /api/expenditures
    else 収支区分＝収入
        FE->>API: POST /api/incomes
    end

    API->>API: バリデーション（型、未来日、金額範囲、メモ200文字以内）
    API->>+DB: カテゴリの存在と category_type を確認
    DB-->>-API: カテゴリ情報

    alt 入力エラー
        API-->>FE: 400 VALIDATION_ERROR / INVALID_AMOUNT / CATEGORY_TYPE_MISMATCH
        FE-->>U: エラーメッセージを項目ごとに表示
    else カテゴリ・ユーザーが存在しない
        API-->>FE: 404 NOT_FOUND
        FE-->>U: エラーメッセージを表示
    else 正常
        API->>+DB: INSERT（expenditures または incomes）
        DB-->>-API: 作成したレコード
        API-->>-FE: 201 Created（作成したレコード）
        alt 「続けて入力」ON
            FE-->>U: 入力欄をクリアしてSCR-002に留まる
        else 「続けて入力」OFF
            FE-->>-U: SCR-001 ホームへ遷移
        end
    end
```

### 3. 収支一覧表示・編集・削除（SCR-003 / FUC-002〜004）

一覧の行をタップすると編集ボトムシート（SCR-003の上に重ねて表示する部品）が開き、保存または削除を行う。

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor U as ユーザー
    participant FE as 画面（React）<br>SCR-003 収支一覧
    participant API as APIサーバー<br>（Node.js）
    participant DB as DB<br>（PostgreSQL）

    Note over U,DB: 一覧表示（FUC-004）
    U->>+FE: メニュー「収支一覧」をタップ
    FE->>+API: GET /api/expenditures（limit / offset / date_from / date_to）
    API->>+DB: SELECT expenditures（is_delete = false）
    DB-->>-API: 支出レコード
    API-->>-FE: 200 OK（data / total）
    FE->>+API: GET /api/incomes（同じ条件）
    API->>+DB: SELECT incomes（is_delete = false）
    DB-->>-API: 収入レコード
    API-->>-FE: 200 OK（data / total）
    FE-->>-U: 支出・収入の一覧を表示

    U->>+FE: 行をタップ
    FE-->>-U: 編集ボトムシートを表示

    alt 保存（FUC-002）
        U->>+FE: 内容を修正して「保存」
        FE->>+API: PATCH /api/expenditures/{id}（変更した項目のみ）
        API->>API: バリデーション（登録時と同条件）
        API->>+DB: UPDATE expenditures
        DB-->>-API: 更新後のレコード
        API-->>-FE: 200 OK（更新後のレコード）
        FE-->>-U: シートを閉じて一覧を更新
    else 削除（FUC-003）
        U->>+FE: 「削除」をタップ
        FE->>+API: DELETE /api/expenditures/{id}
        API->>+DB: UPDATE expenditures SET is_delete = true
        DB-->>-API: 更新件数
        API-->>-FE: 204 No Content
        FE-->>-U: シートを閉じて一覧から除外
    end

    Note over FE,API: 収入の行は /api/incomes/{id} を呼ぶ。<br>指定IDが存在しない場合は 404 NOT_FOUND。<br>支出⇔収入の区分変更は不可（削除して登録し直す）。
```

### 4. 固定費の一覧表示・登録・編集・削除（SCR-005・SCR-004 / FUC-005〜008）

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor U as ユーザー
    participant FE as 画面（React）<br>SCR-005 固定費一覧<br>SCR-004 固定費登録
    participant API as APIサーバー<br>（Node.js）
    participant DB as DB<br>（PostgreSQL）

    Note over U,DB: 一覧表示（FUC-008）
    U->>+FE: メニュー「固定費」をタップ
    FE->>+API: GET /api/fixed-expenditures
    API->>+DB: SELECT fixed_expenditures（is_delete = false）
    DB-->>-API: 固定費レコード
    API-->>-FE: 200 OK（data / total）
    FE-->>-U: SCR-005 固定費一覧を表示

    alt 新規登録（FUC-005）
        U->>+FE: 「固定費を登録」→ 名称・カテゴリ・金額・頻度・開始日を入力し「登録する」
        FE->>+API: POST /api/fixed-expenditures
        API->>API: バリデーション（必須項目、金額範囲、開始日形式等）
        API->>+DB: カテゴリ種別を確認
        DB-->>-API: 確認結果
        alt エラー
            API-->>FE: 400 VALIDATION_ERROR / CATEGORY_TYPE_MISMATCH など
            FE-->>U: エラーメッセージを表示
        else 正常
            API->>API: 次回計上日を計算（開始日が明日以降なら開始日、今日以前なら今日の翌月以降で最初の計上日）
            API->>+DB: INSERT fixed_expenditures
            DB-->>-API: 作成したレコード
            API-->>-FE: 201 Created
            FE-->>-U: SCR-005 固定費一覧へ戻る
        end
    else 編集（FUC-006）
        U->>+FE: 行をタップ → SCR-004（編集モード）で修正し「登録する」
        FE->>+API: PATCH /api/fixed-expenditures/{id}
        API->>API: 開始日・頻度が変わった場合は次回計上日を再計算
        API->>+DB: UPDATE fixed_expenditures
        DB-->>-API: 更新後のレコード
        API-->>-FE: 200 OK
        FE-->>-U: SCR-005 固定費一覧へ戻る
    else 削除（FUC-007）
        U->>+FE: SCR-004（編集モード）で「削除」
        FE->>+API: DELETE /api/fixed-expenditures/{id}
        API->>+DB: UPDATE fixed_expenditures SET is_delete = true
        DB-->>-API: 更新件数
        API-->>-FE: 204 No Content
        FE-->>-U: SCR-005 固定費一覧へ戻る
    end
```

### 5. 固定費自動計上（バックグラウンド処理 / FUC-009）

画面を持たない処理のため、ユーザーではなくスケジューラ（cron）が起点となる。計上結果はSCR-001・SCR-003に反映される。

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor S as スケジューラ<br>（cron・日次）
    participant B as 自動計上バッチ<br>（Node.js）
    participant DB as DB<br>（PostgreSQL）

    S->>+B: 自動計上処理を起動
    B->>+DB: 計上対象の固定費を取得<br>（次回計上日＝本日）
    DB-->>-B: 対象の固定費一覧

    loop 対象の固定費ごと
        B->>+DB: INSERT expenditures（カテゴリ・金額・計上日・ユーザ＝fixed_user）
        DB-->>-B: 作成したレコード
        B->>B: 次の計上日を計算（毎月：翌月の開始日dd／毎年：翌年の開始日MM/dd。該当日がない月は月末日）
        B->>+DB: UPDATE fixed_expenditures（次回計上日）
        DB-->>-B: 更新件数
    end

    B-->>-S: 処理結果（計上件数）

    Note over B,DB: 未決事項（テーブル定義書 7章）<br>・生成した支出の元の固定費を参照するFK
```

### 6. 支出削減設定（SCR-008・SCR-009 / FUC-010, FUC-014）

category_classificationにレコードがあるカテゴリを「削減対象」、ないカテゴリを「維持対象」として扱う。SCR-008で削減対象・優先度を選び、SCR-009で削減金額を入力して「保存する」で一括置き換えする。SCR-008からSCR-009へ進む時点ではDBに保存しない。

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor U as ユーザー
    participant FE8 as 画面（React）<br>SCR-008 支出削減設定
    participant FE9 as 画面（React）<br>SCR-009 削減金額設定
    participant API as APIサーバー<br>（Node.js）
    participant DB as DB<br>（PostgreSQL）

    U->>+FE8: メニュー「支出削減」をタップ
    FE8->>+API: GET /api/categories?category_type=01&user_id=1
    API->>+DB: SELECT categories（デフォルト＋自分が作成、is_delete=false）
    DB-->>-API: 支出用カテゴリ一覧
    API-->>-FE8: 200 OK（data）
    FE8->>+API: GET /api/category-classifications?reduction_target_user=1
    API->>+DB: SELECT category_classification（categoriesと結合）
    DB-->>-API: 削減対象カテゴリ一覧（優先度・削減金額）
    API-->>-FE8: 200 OK（data）
    FE8->>FE8: 一覧にないカテゴリを「維持対象」として表示
    FE8-->>-U: カテゴリごとの区分・優先度を表示

    U->>+FE8: 区分・優先度を変更して「次へ」
    FE8->>FE8: 選択内容（カテゴリ・優先度）を画面側で保持（DBには保存しない）
    FE8->>-FE9: 遷移（選択内容を引き継ぐ）
    activate FE9
    FE9-->>U: 削減対象を優先度順に表示（保存済みの削減金額があれば初期表示）
    deactivate FE9

    U->>+FE9: 削減金額を入力して「保存する」
    FE9->>FE9: バリデーション（削減金額 1〜999,999円）
    FE9->>+API: PUT /api/category-classifications（reduction_target_user / items）
    API->>API: バリデーション（削減対象1〜3件、優先度1〜3で重複・欠番なし、削減金額1〜999999、カテゴリの重複なし）
    API->>+DB: BEGIN
    API->>DB: 対象ユーザーの既存レコードを削除
    API->>DB: items の内容（優先度・削減金額を含む）をINSERT
    alt エラー
        API->>DB: ROLLBACK（何も変更しない）
        DB-->>API: 完了
        API-->>FE9: 400 INVALID_AMOUNT / CATEGORY_TYPE_MISMATCH など / 404 NOT_FOUND
        FE9-->>U: エラーメッセージを表示（画面に留まる）
    else 正常
        API->>DB: COMMIT
        DB-->>-API: 完了
        API-->>-FE9: 200 OK（保存後の内容）
        FE9-->>-U: ページ上部に「支出削減頑張りましょう」を表示し、SCR-008へ遷移
    end

    Note over FE8,API: SCR-008で削減対象を0件にして「次へ」を押した場合は、<br>「削減対象は1個以上選択してください」を表示し、SCR-009へは進まない。
```

### 6-2. カテゴリ設定（SCR-006 / FUC-015〜018）

カテゴリの追加・編集・削除はSCR-006上のカテゴリ編集シートで行う。編集・削除できるのは自分が作成したカテゴリのみ。

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor U as ユーザー
    participant FE as 画面（React）<br>SCR-006 カテゴリ設定
    participant API as APIサーバー<br>（Node.js）
    participant DB as DB<br>（PostgreSQL）

    U->>+FE: メニュー「カテゴリ設定」をタップ
    FE->>+API: GET /api/categories?category_type=01&user_id=1
    API->>+DB: SELECT categories（デフォルト＋自分が作成、is_delete=false）
    DB-->>-API: カテゴリ一覧
    API-->>-FE: 200 OK（data・editable）
    FE-->>-U: カテゴリ一覧を表示（デフォルトは「標準」タグ）

    U->>+FE: 「＋ カテゴリを追加」→ 名称・アイコンを入力して「追加する」
    FE->>+API: POST /api/categories
    API->>+DB: INSERT categories（default_category=false）
    alt 名称が重複
        DB-->>API: UNIQUE制約違反
        API-->>FE: 409 DUPLICATE_CATEGORY_NAME
        FE-->>U: 「同じ名前のカテゴリがすでにあります」を表示
    else 正常
        DB-->>-API: 作成したレコード
        API-->>-FE: 201 Created
        FE-->>-U: シートを閉じて一覧を再取得、「カテゴリを追加しました」
    end

    U->>+FE: 自分のカテゴリの行 →「削除」→ 確認ダイアログで「削除」
    FE->>+API: DELETE /api/categories/{category_id}
    API->>+DB: 有効な固定費で使用中か確認
    alt 固定費で使用中
        DB-->>API: 使用中
        API-->>FE: 409 CATEGORY_IN_USE
        FE-->>U: 「固定費で使用中のため削除できません」を表示
    else 使用されていない
        API->>DB: BEGIN
        API->>DB: categories を論理削除
        API->>DB: 自分の category_classification（該当カテゴリ）を論理削除
        API->>DB: 残りの削減対象の reduction_number を1から連番に詰め直す（削減対象だった場合）
        API->>DB: COMMIT
        DB-->>-API: 完了
        API-->>-FE: 204 No Content
        FE-->>-U: シートを閉じて一覧を再取得、「カテゴリを削除しました」
    end
```

### 7. グラフ・レポート表示（SCR-007 / FUC-011〜013）

いずれも読み取り専用の集計APIで、集計はDB側（GROUP BY）で行う。

```mermaid
%%{init: {"themeCSS": ".actor-line { stroke-dasharray: 4 4; }"}}%%
sequenceDiagram
    actor U as ユーザー
    participant FE as 画面（React）<br>SCR-007 グラフ・レポート
    participant API as APIサーバー<br>（Node.js）
    participant DB as DB<br>（PostgreSQL）

    U->>+FE: フッター「レポート」またはホームの「詳しく見る」をタップ

    FE->>+API: GET /api/reports/monthly-summary（date_from / date_to）
    API->>+DB: 月別の収入・支出を集計
    DB-->>-API: 集計結果
    API-->>-FE: 200 OK（月次収支推移）

    FE->>+API: GET /api/reports/category-breakdown（date_from / date_to）
    API->>+DB: カテゴリ別の支出を集計
    DB-->>-API: 集計結果
    API-->>-FE: 200 OK（カテゴリ別支出）

    FE->>+API: GET /api/reports/reduction-targets（date_from / date_to）

    DB-->>-API: 集計結果
    API-->>-FE: 200 OK（削減対象カテゴリ内訳）

    FE->>FE: グラフを描画（Recharts）
    FE-->>-U: グラフ・レポート画面を表示

    Note over FE,API: 期間指定が不正（date_from が date_to より後）の場合、<br>各APIは 400 VALIDATION_ERROR を返す。
```
